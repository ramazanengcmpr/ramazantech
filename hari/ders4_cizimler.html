Hafta 3 · 1. Ders: API, Confluent, RAG ve MCP

Hari, bu dersin çizimleri ve kısa açıklamaları burada.

1. API nasıl çalışır

API, bir yazılımın başka bir yazılımdan bir şey istemesi için kuralları belli bir kapı; restorandaki garson gibi. Uygulama bir istek gönderir, cevap genelde JSON formatında döner. Kurumlar API'lerini API gateway üzerinden yönetir (IBM'de API Connect ve webMethods). API'de soran cevabı bekler; event'te ise sistem "şu oldu" diye yayınlar ve ilgilenen herkes aynı anda dinler. "Bakiyem ne?" API ile sorulur; "kart işlemi oldu" event olarak yayınlanır.

2. Confluent'in içi

Confluent'in altında açık kaynak Apache Kafka var. Event'ler topic denen kategorilere yazılır (WhatsApp grubu gibi). Topic'e yazan sisteme producer, okuyana consumer denir; her consumer kendi hızında okur ve nerede kaldığı (offset) ayrı tutulur. Kafka cluster'ındaki her sunucuya broker denir; topic parçalara bölünüp broker'lara dağıtılır ve kopyalanır. Event'ler okunduktan sonra silinmez, belirlenen süre saklanır. Confluent bunun üstüne connector'lar (kod yazmadan bağlanma), Schema Registry (format sözleşmesi), Flink (akarken işleme) ve Tableflow (tablo olarak açma) ekler.

3. RAG

Dil modelleri kurumun iç bilgisini bilmez; bilmediğini sorarsan bazen uydurur (hallucination). RAG (Retrieval Augmented Generation), cevaplamadan önce ilgili bilgiyi bulup modele verir. Hazırlıkta dokümanlar parçalanır, embedding'e çevrilir ve vector database'e konur. Soru anında soruya anlamca en yakın parçalar bulunur ve soruyla birlikte modele verilir; model cevabı o parçalardan üretir ve kaynağını gösterebilir. RAG'in kaynağı çoğunlukla ECM'deki dokümanlardır.

4. MCP ve MCP katalogları

Agent, sadece cevap vermeyen, araç kullanarak iş de yapan AI'dır. MCP (Model Context Protocol), agent'ların sistemlere bağlanması için açık standart; "AI için USB-C" deniyor. MCP server bir sistemi AI'a açan adaptördür ve sunduğu araçları AI'ın anlayabileceği şekilde tarif eder; MCP client ise agent'ın kendisi ya da onu çalıştıran uygulamadır. Kurumda yüzlerce MCP server olabileceği için MCP kataloğu hangilerinin onaylı olduğunu ve kimin erişebileceğini tutar (uygulama mağazası gibi); MCP gateway de yetkiyi kontrol eder ve her çağrıyı kaydeder. IBM tarafında watsonx Orchestrate agent'ları ve araç kataloğunu, watsonx.governance agent ve araç envanterini yönetir.
